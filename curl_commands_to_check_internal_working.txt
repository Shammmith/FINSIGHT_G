## Local Smoke Test — Run These in a NEW Third Terminal

Keep both uvicorn terminals running. Open a fresh terminal (not inside either venv — just a plain terminal is fine for curl).

### Step 1 — Confirm Both Health Endpoints

```powershell
curl http://localhost:8000/health
curl http://localhost:8001/health
```

**Expected both:**

```json
{"status": "ok"}
```

### Step 2 — Register a User

```powershell
curl -X POST http://localhost:8000/api/v1/auth/register `

  -d "{\"email\": \"test@finsight.com\", \"password\": \"TestPass123!\"}"
```

**Expected:**
```json
{"id": "...", "email": "test@finsight.com", "role": "user"}
```

### Step 3 — Login and Capture Token

```powershell
curl -X POST http://localhost:8000/api/v1/auth/login `
  -H "Content-Type: application/x-www-form-urlencoded" `
  -d "username=test@finsight.com&password=TestPass123!"
```

**Expected:**
```json
{"access_token": "eyJ...", "token_type": "bearer"}
```

Copy the token value. Then set it as a variable — in PowerShell:
```powershell
$TOKEN = "eyJ..."
```

### Step 4 — Create Test CSV and Upload

First create the file:
```powershell
@"
date,description,amount
2024-01-05,SBUX COFFEE #4521,-5.75
2024-01-06,STARBUCKS STORE 1102,-4.50
2024-01-07,UBER TRIP,-12.30
2024-01-08,SALARY CREDIT ACME CORP,3000.00
2024-01-09,NETFLIX.COM,-15.99
2024-01-10,WALMART SUPERCENTER,-87.42
2024-01-12,COSTA COFFEE LTD,-6.20
2024-01-15,SPOTIFY PREMIUM,-9.99
"@ | Out-File -FilePath test_statement.csv -Encoding utf8
```

Then upload it:
```powershell
curl -X POST http://localhost:8000/api/v1/statements/upload `
  -H "Authorization: Bearer $TOKEN" `
  -F "file=@test_statement.csv"
```

**Expected:**
```json
{"statement_id": "...", "transactions_parsed": 8}
```

Set the statement ID:
```powershell
$STATEMENT_ID = "paste-statement-id-here"
```

---

### Step 5 — Trigger Clustering Job

```powershell
curl -X POST http://localhost:8000/api/v1/cluster `
  -H "Authorization: Bearer $TOKEN" `
  -H "Content-Type: application/json" `
  -d "{\"statement_id\": \"$STATEMENT_ID\"}"
```

**Expected:**
```json
{"job_id": "...", "status": "QUEUED"}
```

Set the job ID:
```powershell
$JOB_ID = "paste-job-id-here"
```

---

### Step 6 — Poll Job Status

Run this every 5-10 seconds until status is `DONE`:
```powershell
curl http://localhost:8000/api/v1/cluster/$JOB_ID/status `
  -H "Authorization: Bearer $TOKEN"
```

**Expected progression:**
```json
{"status": "QUEUED"  ...}
{"status": "PROCESSING" ...}
{"status": "DONE", "k_optimal": 4, "silhouette_score": 0.10...}
```

⏱ This will take **15-30 seconds** on first run locally — the ML Engine is embedding 8 transactions through SBERT. Subsequent runs are faster since the model is already loaded in memory.

---

### Step 7 — Verify in Supabase (Critical Semantic Check)

While the job runs or after it completes, go to:

**Supabase Dashboard → SQL Editor** and run:

```sql
SELECT cleaned_description, cluster_id 
FROM transactions 
WHERE statement_id = 'paste-your-statement-id-here'
ORDER BY cluster_id;
```

**What to confirm:**
- All 8 rows have a non-null `cluster_id`
- `sbux coffee 4521`, `starbucks store 1102`, and `costa coffee ltd` all share the **same** `cluster_id` value
- `salary credit acme corp` has a **different** `cluster_id` from the coffee ones

This is the semantic clustering proof — the most important verification in the entire test.

The issue is that **PowerShell uses backtick (`) for line continuation but your terminal is CMD** (Command Prompt), not PowerShell. The backtick is being treated as a literal character, not a line break, which breaks the multi-line curl commands.

Two options — pick whichever terminal you prefer:

---

## Option A: Switch to PowerShell (Recommended)

In VS Code, click the dropdown arrow next to the `+` in the terminal panel → select **"PowerShell"** (not Command Prompt). Then re-run the commands exactly as written with the backtick line continuations — they'll work correctly.

OR open PowerShell directly:
```
Start Menu → search "PowerShell" → open it
cd C:\Users\shamm
```
